# Dioxus specialized task router

Read only the reference that matches the current task:

- Create or enable a target, configure Cargo features, set `Dioxus.toml`, or select a launch command: `references/project-setup.md`
- Use Store state, lenses, or Store domain operations: `references/state-store.md`
- Add nests, layouts, redirects, query or hash state, catch-all routes, or scroll restoration: `references/advanced-routing.md`
- Configure CSS modules, Tailwind scanning, or dynamic assets: `references/assets-tailwind.md`
- Add forms, cookies, sessions, identity, or authentication layers: `references/fullstack-auth.md`
- Add SSE, typed streams, WebSockets, files, bytes, or multipart forms: `references/fullstack-streaming.md`
- Add an Axum router, middleware, injected state, custom extractor, or custom response: `references/server-integration.md`
- Add a web manifest, service worker, public PWA asset, base path, or custom HTML: `references/web-pwa.md`
- Add desktop menus, trays, windows, Wry events, child surfaces, WGPU, or an external document host: `references/desktop-integration.md`
- Add mobile permissions, FFI, Gradle, Swift packages, widgets, Live Activities, or platform fallbacks: `references/mobile-native.md`

If one explicit task covers more than one area, read only the references for those areas. Do not read all references by default. Ordinary component edits use the automatic Dioxus context and do not need this skill.
